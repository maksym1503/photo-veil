# ADR-007 — Freemium exports and native subscriptions

Accepted 2026-10-12 following CTO review. Supersedes ADR-002's inactive/session-based commerce proposal only. Owner explicitly approved two successful exports and monthly/yearly products; Veil's name remains unchanged, supplied product IDs use `vail`.

One shared main-actor coordinator admits a UUID lease before editor/gallery output work, after refreshing verified Apple entitlements. Two successful Save/Share operations are free; repeated destinations count separately. Editing, preview, failure and cancellation are free. Photos commits after Photos success, Gallery after persistence, Share after native activity completion (`completed && error == nil`). The lease remains held through sharing; completion is idempotent. Automatic cloud replication of an already saved output is not another user export. Future explicit upload/export entry points must use this gate.

A versioned, nonsynchronizing device-only Keychain record contains only the count. Corruption/inaccessible storage never resets it. Probe writes before free admission; retain successful consumption in memory on write failure and retry before further free exports. Paid exports leave the unused allowance intact. No photo identifiers, fingerprints, watermark strings, account or backend are needed.

Verified StoreKit 2 current entitlements and transaction updates are the only Pro authority, independent of legal/product loading readiness. Apple includes subscribed/billing-grace transactions and excludes refunded/revoked ones; do not reject grace using the original transaction expiration. Foreground and admission refresh prevent stale local flags. Products must match the allowlist, durations and subscription group. Trial copy requires the actual eligible three-day free-trial offer. Prices/savings derive from StoreKit. Missing real legal URLs disables production purchasing but never restore/recognition. Explicit DEBUG UI-test development override is documented, never compiled into Release.

Alternatives: an account/backend quota adds identity and privacy costs; third-party billing adds an unnecessary dependency; a reservation journal cannot establish whether an external save succeeded after a process kill. Native StoreKit and a success-first counter fit this scope.

Limitations: Photos/activity services and Keychain are not one atomic transaction. A process kill between success and count commit may leave one operation uncounted. Keychain survival across reinstall is not guaranteed; free allowance is per device, not App Store account. Purchases restore across devices through Apple, not Veil accounts. Share completion means activity completion, not downstream delivery. No invented offline extension; Apple-verified cached entitlements govern offline access.

Validation: injected storage/lease tests; native StoreKitTest month/year, trial/renewal/expiration/refund/billing/restore tests; editor/gallery integration and cancellation checks; localized paywall screenshots, accessibility, Release isolation. Production legal publication, App Store Connect agreements/group/pricing/trials and sandbox/device validation remain owner release gates. No production products/services/distribution activated.


## Native StoreKit harness correction

CTO approved a dedicated app-hosted `PhotoVeilCommerceTests` integration target after the first unhosted xctest StoreKit attempt reached an Apple Account prompt instead of a local purchase context. That run was stopped and is not passing evidence. Existing unhosted core tests and test-layer assignments remain; StoreKit transactions alone use the application host. Configuration is bundled only with test runners and explicitly attached to the local Run scheme. Test setup must fail immediately if local StoreKit initialization/product loading fails; never interact with an Apple Account prompt or fall back to live purchases. Release excludes test configuration/overrides.

## StoreKit environment diagnosis (2026-10-12)

CTO approved a bounded comparison using a dedicated free iOS 26.1 simulator after the iOS 26.5 runtime (23F77) rejected configuration writes with `SKInternalErrorDomain Code=3`. Preserve existing simulators, signing configuration and production behavior. Do not inject private StoreKit daemon state or replace native transactions with mocks. A throwing `setSimulatedError(nil, forAPI:)` call alone did not detect the failed activation; actual fixture-product checks must precede purchase/restore, and successful transaction assertions must verify Apple's `.xcode` environment. Runtime comparison results belong in the monetization implementation report; approval of this investigation does not establish successful lifecycle validation.

Native testing exposed a lifecycle observation gap: auto-renew cancellation changes subscription status without necessarily creating a new transaction. CTO approved a dedicated `Product.SubscriptionInfo.Status.updates` observer alongside transaction updates. Verified allowlisted auto-renewable status events trigger the existing verified-current-entitlements scan and offer refresh; status events never grant access themselves. Expired/revoked events must still trigger refresh. Startup remains idempotent, tasks are cancelled on deallocation, revision guards remain, and no extra sync, account or backend is introduced. Native mutation tests await actual events and verify signed expiration/revocation causes rather than assuming StoreKitTest simulation calls publish synchronously.
